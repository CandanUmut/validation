title: Test types, with RAN examples
source: practice
points:
- '<i>In practice:</i> <b>functional:</b> does the feature do what the spec says? Example: handover completes with the right messages in the right order.'
- <i>In practice:</i> <b>performance:</b> how well? Throughput, registration time, handover interruption time.
- <i>In practice:</i> <b>interoperability (IOT):</b> does it work with every phone and chipset? Each modem implementation reads the spec a little differently.
- <i>In practice:</i> <b>regression:</b> did the new build break something that worked?
- '<i>In practice:</i> <b>stress, soak, stability:</b> many users, long runs, repeated cycles: finds leaks, slow degradation, rare races.'
- <i>In practice:</i> <b>negative:</b> wrong inputs, lost messages, timer expiries, rejects.
- <b>Conformance:</b> 3GPP writes formal UE test specifications, for example TS 38.521-1 (NR UE RF conformance, FR1). <i>In practice:</i> protocol conformance and the LTE equivalents (TS 38.523, 36.521, 36.523) are used for certification by industry bodies such as GCF and PTCRB.
say: Functional proves it works, performance proves how well, interoperability proves it works with everyone, regression proves it still works.
trap: Conformance passes do not prove interoperability. Real phones still differ; that is why IOT exists.
