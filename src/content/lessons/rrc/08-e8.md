title: Handover
source: research
points:
- The UE reports (usually an A3 measurement report); the source gNB prepares the target over Xn or through the core, then sends the command.
- <b>NR command:</b> <code>RRCReconfiguration</code> with <code>reconfigurationWithSync</code>. The UE starts <b>T304</b> with the configured <code>t304</code>, syncs to the target, does random access, and sends <code>RRCReconfigurationComplete</code> to the target. LTE uses <code>RRCConnectionReconfiguration</code> with <code>mobilityControlInfo</code>.
- '<b>T304 expiry</b> = reconfiguration-with-sync failure: the UE reverts to the source configuration, stores handover failure information for the RLF report, and starts re-establishment.'
- <b>Conditional handover (CHO):</b> the network gives one or more candidate target cells early, each with an execution condition (such as CondEvent A3). The UE applies the configuration of a candidate whose condition is met.
- <b>Network side (NR):</b> the source sends XnAP HANDOVER REQUEST, the target answers HANDOVER REQUEST ACKNOWLEDGE (carrying the command for the UE), the source sends SN STATUS TRANSFER, the target asks the AMF with NGAP PATH SWITCH REQUEST, and XnAP UE CONTEXT RELEASE frees the source. Without Xn, the source uses NGAP HANDOVER REQUIRED.
say: Report, prepare, command with reconfiguration-with-sync, random access to the target, complete. T304 guards the access; on expiry, re-establish.
trap: A handover that fails one way only often points at the target's random access settings or <code>t304</code>, not at the measurement.
