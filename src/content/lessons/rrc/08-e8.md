title: Handover
source: v1
points:
  - 1. Phone sends a <b>Measurement Report</b>. 2. Source decides and sends a <b>Handover Request</b> to the target (X2 or Xn, or through the core on S1 or NG). 3. Target admits and replies.
  - "4. Source sends the handover command: <code>RRCConnectionReconfiguration</code> with <code>mobilityControlInfo</code> (LTE) or <code>RRCReconfiguration</code> with <code>reconfigurationWithSync</code> (NR)."
  - 5. Phone starts <b>T304</b>, syncs to the target and does random access (usually contention-free).
  - 6. Phone sends Reconfiguration Complete to the target. 7. Target asks the core for a <b>path switch</b>. 8. Source context is released.
  - <b>Failures:</b> too late (radio link fails before the command arrives), too early, wrong cell, T304 expiry (RACH to target failed).
  - <b>Conditional handover (CHO):</b> the command is given early and the phone executes it when a condition is met. Useful when the serving link may die suddenly.
say: Report, prepare, command, random access to the target, complete, path switch.
trap: Handover success rate has a preparation part and an execution part. A drop before the command is not counted as a handover failure unless you look for it.
