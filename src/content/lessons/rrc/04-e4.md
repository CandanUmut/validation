title: 'NAS: attach and registration'
source: research
points:
- '<b>LTE attach</b> (TS 24.301): ATTACH REQUEST with a PDN CONNECTIVITY REQUEST inside, authentication, security mode, ATTACH ACCEPT with ACTIVATE DEFAULT EPS BEARER CONTEXT REQUEST inside, then ATTACH COMPLETE with the bearer accept inside. Attach and the default bearer happen together.'
- '<b>5G registration</b> (TS 24.501): REGISTRATION REQUEST, authentication, security mode, REGISTRATION ACCEPT. The UE returns REGISTRATION COMPLETE when the accept assigns a new 5G-GUTI (always the case in an initial registration) or certain other updates.'
- <b>5G sessions are separate:</b> after registration, the UE sends a PDU SESSION ESTABLISHMENT REQUEST inside an UL NAS TRANSPORT message and starts <b>T3580</b>.
- 'Registration types: initial, mobility registration update, periodic registration update (on <b>T3512</b> expiry), and emergency.'
- <b>Authentication (AKA):</b> the network sends RAND and AUTN; the USIM checks AUTN and computes RES. In 5G the UE sends <b>RES*</b>, derived from RES as defined in TS 33.501.
say: LTE attach brings the default bearer with it. 5G registers first, then sets up PDU sessions separately, and answers authentication with RES*.
trap: 'Registration Accept without Registration Complete is not always an error: the UE only has to send it when something like a new 5G-GUTI needs acknowledging.'
